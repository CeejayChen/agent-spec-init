# 防御模式

来之不易的缺陷类型规则：下面每条都对应一类真实发生或险些发生的缺陷，写成防止复发的规则。写生命周期、子进程或清理代码之前先读本文。

## 独立报告正交的结果

一个结果可以同时是几件事——进程可能既超时又以 0 退出，因为它捕获了信号。每个独立事实单独呈现，绝不要把一个标志的报告嵌进另一个分支，否则调用方会把被截断的运行读成干净的成功。

## 清理必须到达静止，而不只是发出请求

如果清理只发出 kill 或 abort 就返回，工作并未停止，会留下孤儿进程。等待子进程退出，并在 kill 之前关闭注册表，让迟到的完成保持安静。门禁运行器在打印汇总前会等待每个已启动的门禁，正是这个原因。

## 在分发器中兜住回调异常

用户提供的监听器抛错时，不能让它所在的 Promise 被拒绝，也不能让后续监听器饿死。用 try/catch 包住分发循环并记录日志；一个坏订阅者永远不该破坏核心生命周期。

## 不要把环境或可预测路径交给不可信输出

被启动的命令拿到经过清洗的环境（去掉 `*KEY*`、`*SECRET*`、`*TOKEN*`、`*PASSWORD*`），凭据才不会泄漏到输出里。临时与溢出文件使用私有目录、随机文件名和仅所有者可访问的独占打开——可预测的全局可读路径会招来符号链接竞争与信息泄露。

## 先校验再写入

在触碰目标仓库之前校验参数、模板与 JSON manifest。脚手架会解析既有的 `package.json`，遇到非法 JSON 就报错而不是覆盖；写了一半的规范体系比没有运行更糟。

## 对链接形态的路径使用 unlink

可能为符号链接或 junction 的路径，先用 `lstat` 判断再 `unlink`：unlink 只删除链接、拒绝真实目录，因此不会顺着链接进入目标。递归删除只用于确定是真实目录的路径。
