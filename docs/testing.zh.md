# 测试策略

agent-spec-init 如何分层测试，以及让绿色套件保持可信的规则。命令见根目录 [AGENTS.md](../AGENTS.md)。

## 分层

- **单元**（`npm test`）：渲染、探测、规划与落盘都针对临时目录和内存中的事实运行。断言文件内容与结果，不断言控制台措辞。
- **集成**（`npm test`，`tests/scaffold.spec.ts`）：在临时目录真实生成一次，再用 `tsx` 或 Python 运行生成项目自己的门禁。
- **负向控制**（`npm test`）：硬换行的段落、缺 JSDoc 的导出、格式错误的 Agent Note 必须让对应门禁变红。不会失败的门禁等于没有被证明可用。
- **模板门禁**（`npm run verify-templates`）：渲染每种栈配置，检查残留占位符、自身预算清单，以及是否有未被使用的模板。

## 优先使用真实实现而非 mock

集成测试运行生成的门禁脚本，而不是断言脚本源码。它们启动本地 `tsx` 与已安装的 Python 解释器，因此错误的 import 或错误的命令会让测试失败。

## 验证世界，而不是验证自述

断言在运行之后从磁盘读取文件并检查进程退出码。没有任何测试因为报告字符串说成功就通过；JSON 报告单独测结构，文件系统单独测结果。

## 测试真实入口路径

`tests/cli.spec.ts` 用真实 argv 调用 `main`，覆盖 `--dry-run`、`--json` 与非法模板。只构造 options 对象会漏掉参数解析与退出码映射。

## 何时需要快照

本仓库不使用快照。生成文档通过渲染后检查关键属性来断言：无占位符、结尾恰好一个换行、预算内、链接可解析。将来若出现表示稳定的输出格式，再在归属模块旁放期望输出夹具。

## 交付前的人工检查

改动文档时，确认每段一个物理行、相对链接可解析、字数在 `scripts/doc-budgets.manifest.json` 预算内。改动双语文档时，更新三元组并运行 `npx tsx scripts/verify-translation-pairing.ts --write <文件>`。
