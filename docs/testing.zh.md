# 测试策略



本项目如何逐层测试，以及保持绿色套件有意义的规则。命令在根 [AGENTS.md](../AGENTS.md) 中；关联的 Agent Notes 保留了决策理由。

## 层级

- **单元**（`npm run test`）：测试与其所测代码区域放在一起。优先测试边界情况、错误路径、事件顺序、并发竞争，以及用于契约回归的永久测试。
- **覆盖率门禁**（`npm run test:coverage`）：逐文件覆盖率强制执行。未覆盖的行通常是门禁标记为应删除的死代码，而非需要补写的缺失测试。行覆盖率是必要条件，永远不是充分条件——它证明行被执行了，而非功能按发布方式工作。
- **集成 / e2e**：针对真实服务或组合系统的测试。每个套件在其配置不可用时自动跳过，使 CI 对没有访问权限的贡献者保持绿色。

## 规范如何执行

Fork 的工作进程同时运行多个规范文件。只有进程是隔离的：端口、可预测路径、外部命名空间和继承的子进程不是。通过清理来拥有每个获取的资源，并将仅在单独运行时才通过的规范视为规范中的缺陷。

## 优先使用真实实现而非 mock

仅 mock 昂贵或非确定性的边界（外部 API、网络、时钟）；保持下游一切真实。手工编写的替代品证明桥接能传输字节，而非发布工具按断言方式工作。

## 验证世界，而非自我报告

e2e 断言重新运行命令或从外部重新读取文件；对代理自身输出的关键词探测会让作弊的代理通过。断言未修改的文件字节完全相同。e2e 测试拥有自己的资源：在测试中创建，在 `afterEach` 中清理。

## 测试真实入口路径

产品可见的插件需要非单元的组合测试。手工构建的插件套件是不够的：通过加载器和进程启动仅测试用配置，仅 mock 外部服务或非确定性输入，并断言模型可见的、持久的或用户可见的输出。

## 何时需要快照测试

每个非平凡的模型、协议或人类可见变更在同一 PR 中添加或更新一个录制会话场景。不由录制会话驱动的预期输出与其拥有模块一起放在 `tests/expected/` 下。
